# MYSTICAL BEASTS ALLIANCE — Admin / Inventory / Deleted History

## เวอร์ชันนี้แก้ไข
- ลบแถบสถานะ ADMIN / Password verification ที่ซ้ำซ้อนออกจากหน้า Admin
- หน้า Admin เปิดดูสถานะได้ทันที
- การลบ WORK LOG ยังคงถาม Password เฉพาะตอนกดลบจริง เพื่อไม่ให้การยืนยันซ้ำซ้อน
- Admin แสดงจำนวนรวมในคลังจากคอลัมน์ `จำนวน` และแสดงรายการคลังพร้อมหน่วยแบบเรียลไทม์
- เมื่อสั่งลบ WORK LOG ระบบจะย้อนรายการ INVENTORY ที่เกี่ยวข้องก่อน
- ก่อนลบ WORK LOG จริง ระบบจะคัดลอกข้อมูลไปยังแท็บ `DELETED WORK LOG`
- หน้า Admin แสดงประวัติรายการที่ลบแล้ว พร้อมวันที่ลบ เหตุผล และรูปเดิมถ้ามี
- ซิงก์ `DELETED WORK LOG` ทุก 15 วินาทีเช่นเดียวกับข้อมูลหลัก

## สำคัญ
ต้องนำ `Code.gs` เวอร์ชันนี้ไป Deploy เป็น Web App เวอร์ชันใหม่ หลังแก้ Apps Script แล้วจึง Deploy/อัปเดต Web App ให้ใช้เวอร์ชันใหม่

ระบบจะสร้างแท็บ `DELETED WORK LOG` อัตโนมัติเมื่อมีการลบ WORK LOG ครั้งแรก

รายการที่ถูกลบด้วยระบบเวอร์ชันเก่าก่อนมี `DELETED WORK LOG` จะไม่สามารถสร้างข้อมูลย้อนหลังแบบครบถ้วนได้โดยอัตโนมัติ เพราะข้อมูลต้นฉบับถูกลบไปแล้ว

## ระบบขอลบ WORK LOG + การคืนคลัง (เวอร์ชันนี้)
- สมาชิกสามารถกด `ขอลบรายการ` จาก WORK LOG และส่งคำขอไปยัง Admin ได้
- การส่งคำขอ **ยังไม่เปลี่ยนจำนวน INVENTORY และยังไม่คืนของ**
- หากมีคำขอของ WORK ID เดิมที่สถานะ `PENDING` อยู่แล้ว ระบบจะไม่สร้างคำขอซ้ำ
- Admin จะเห็นคำขอในหน้า Admin และเลือก `อนุมัติ` หรือ `ไม่อนุมัติ`
- `อนุมัติ` → ระบบลบ WORK LOG และย้อนรายการ INVENTORY ที่เกิดจาก WORK ID นั้นตามจำนวนธุรกรรมจริง ก่อนเก็บสำเนาไว้ใน `DELETED WORK LOG`
- `ไม่อนุมัติ` → WORK LOG และ INVENTORY ไม่เปลี่ยนแปลง
- Admin สามารถลบ WORK LOG เองได้โดยตรงเช่นเดิม และการลบโดย Admin จะย้อน INVENTORY ตามธุรกรรมของ WORK ID นั้นเช่นกัน
- การย้อนคลังไม่ให้ผู้ใช้กรอกจำนวนเอง ระบบจะใช้จำนวนที่บันทึกไว้ใน `INVENTORY LOG` เท่านั้น
- ป้องกันการลบซ้ำของ WORK ID ที่ถูกลบออกจาก WORK LOG แล้ว และคำขอที่ไม่อยู่ในสถานะ `PENDING` จะดำเนินการซ้ำไม่ได้
- `DELETED WORK LOG` จะเก็บ `Delete Source` ว่าลบโดย Admin โดยตรงหรือผ่านคำขอ และเก็บ `Delete Request ID` เมื่อมาจากคำขอ

### การติดตั้ง
1. ใช้ `Code(2).gs` แทน `Code.gs` ใน Apps Script
2. ใช้ `index(3).html` แทน `index.html`
3. ใช้ `appsscript(2).json` แทน manifest เดิม
4. Deploy Web App เป็นเวอร์ชันใหม่ และใช้ `/exec` URL เดิม/ล่าสุดตามที่ระบบกำหนด
5. เปิด Admin แล้วตรวจส่วน `คำขอลบที่รออนุมัติ`
6. ทดสอบด้วย WORK LOG ที่มีการเบิกคลัง: ส่งคำขอลบก่อน แล้วตรวจว่า Inventory ยังเท่าเดิม จากนั้น Admin อนุมัติและตรวจว่าจำนวนถูกคืนกลับเท่ากับจำนวนที่เบิกจริง
